# 해결한 문제들

실제로 겪은 문제를 **상황 → 원인 → 해결 → 배운 점** 순서로 적었습니다.

---

## 1. 배포만 하면 사이트 전체가 502

**상황:** 코드를 고쳐 api 컨테이너만 다시 만들면 모든 API가 502로 멈췄습니다. 출시 뒤 첫 업데이트 때 바로 터졌을 문제입니다.

**원인:** nginx는 시작할 때 `proxy_pass http://api:8800`의 `api`를 IP로 한 번 바꿔 두고 계속 씁니다. api 컨테이너가 다시 만들어지면 IP가 바뀌는데, nginx는 옛 IP로 계속 보냈습니다.

**해결:** Docker 내부 DNS를 `resolver 127.0.0.11 valid=10s`로 지정하고, `proxy_pass`에 변수를 써서 요청 때마다 주소를 다시 찾게 했습니다. api만 다시 만들어도 200이 나오는 것을 직접 재현해 확인했습니다.

**배운 점:** "시험은 통과"와 "운영에서 된다"는 다릅니다. 운영과 같은 도커 구성으로 배포 동작까지 직접 해 봐야 보이는 문제가 있습니다.

## 2. GitHub CI가 40번 연속 실패

**상황:** 로컬(Windows)에서는 시험이 모두 통과하는데, GitHub Actions(리눅스)는 확인한 최근 40번이 모두 실패였습니다.

**원인:** 한 가지가 아니라 다섯 가지가 겹쳐 있었고, 앞 단계가 실패하면 뒤는 아예 돌지 않아 하나를 고치면 다음 것이 드러났습니다.

1. `#!`가 있는 스크립트 22개에 실행 권한이 없어 린트(EXE001) 실패 — Windows에는 실행 권한 개념이 없어 로컬에서는 안 보임
2. 프론트엔드 FCPXML 시험이 `backend/.venv`의 파이썬만 찾음 — CI의 프론트엔드 작업에는 그 폴더가 없음
3. `pytest`를 바로 실행하면 `app` 모듈을 못 찾음 — 로컬은 `python -m pytest`라 현재 폴더가 경로에 들어갔음
4. Windows에서만 생기는 오류(WinError 50)를 다루는 시험이 리눅스에서도 돎
5. 리눅스용 imageio-ffmpeg에는 자막을 그리는 `drawtext` 필터가 없음 — 운영 도커는 시스템 ffmpeg를 따로 설치해 쓰고 있었음

**해결:** git에 실행 권한 표시, 시스템 파이썬 대체, `pytest.ini`에 `pythonpath`, Windows 전용 표시, CI에 ffmpeg·한글 글꼴 설치. 리눅스에서 백엔드 1,296개·프론트엔드 551개가 통과했습니다.

**배운 점:** CI 환경은 운영 환경과 같아야 의미가 있습니다. 운영 Dockerfile에 있던 결정(시스템 ffmpeg)이 CI에는 빠져 있었습니다.

## 3. AI 키가 없으면 13분 기다린 뒤 영어 오류

**상황:** 운영 모드 도커에서 11분 영상을 올려 보니, 업로드와 음성 인식(3분)까지 끝난 뒤 `Missing credentials. Please pass an api_key...`라는 영어 문장과 함께 실패했습니다.

**원인:** 하이라이트 고르기는 LLM이 꼭 필요한데, 키를 그 단계에 가서야 확인했습니다. 그리고 SDK의 "키 없음" 오류는 분류되지 않아 원문이 그대로 화면에 나갔습니다.

**해결:**
- 키가 없으면 **업로드를 시작하기 전에** 503과 함께 "긴 영상에서 쇼츠 고르기는 AI 키가 있어야 해요"라고 안내
- `/api/longform/limits`에 `ai_ready`를 넣어 화면이 미리 알 수 있게 함
- AI 오류 분류에 `MISSING_KEY`를 추가해 어디서 나든 한글로 보여 주고 다시 시도하지 않음

**배운 점:** 실패할 수밖에 없는 조건은 사용자가 시간을 쓰기 **전에** 확인해야 합니다.

## 4. 14일 보관 정리가 실제로는 돌지 않음

**상황:** 긴 영상 결과는 14일 보관한다고 안내했지만 파일이 계속 쌓였습니다. 작업 하나에 원본 복사본까지 수 GB입니다.

**원인:** 정리 함수는 관리자 버튼으로만 돌았고, 돌아도 완성 영상 이름(`short_01.mp4`)을 못 알아봐 "결과 없는 작업"으로 여겼습니다. "대기"나 "인식 중"인 작업도 끝난 작업으로 볼 수 있었습니다.

**해결:** 1시간마다 도는 정기 정리에 넣고, 상태별 규칙을 다시 짰습니다.
- 끝난 작업: 하루 뒤 중간 파일, 14일 뒤 나머지
- 실패한 작업: 하루 뒤
- 14일 동안 아무 변화가 없는 멈춘 작업: 정리
- 대기·인식·렌더링 중인 작업: 건드리지 않음

지운 작업은 최소 정보만 남겨 화면에 "보관 기간이 지나 지웠어요"를 보여 줍니다. 시험 8개를 추가했습니다.

**배운 점:** 안내 문구(개인정보처리방침 포함)와 실제 동작이 맞는지 코드로 확인해야 합니다.

## 5. 백업 복원이 zip 안의 무엇이든 덮어씀

**상황:** 백업 zip을 복원하는 명령이 zip에 든 파일이면 코드 파일(`app/main.py` 같은 것)까지 서버 폴더에 그대로 덮어썼습니다.

**해결:** 백업이 실제로 만드는 것(`.env`, 맨 위나 `data/` 안의 SQLite 파일)만 허용 목록으로 꺼내고, 나머지는 건너뛰며 기록합니다. 복원 전에는 지금 상태를 `pre_restore_` zip으로 먼저 남깁니다.

**배운 점:** "우리가 만든 파일만 들어온다"는 가정은 언젠가 깨집니다. 받는 쪽에서 허용 목록으로 지킵니다.

## 6. 운영 서버 버전이 "unknown"

**상황:** 화면 아래 버전과 `/api/health`의 커밋이 운영에서는 늘 "unknown"이었습니다.

**원인:** 도커 이미지 안에는 `.git`이 없어 커밋을 물어볼 곳이 없었습니다.

**해결:** `deploy.sh`가 커밋 번호를 빌드 인자로 넘기고, 백엔드 이미지는 그 값을 환경변수로 품습니다. 그래서 되돌린 옛 이미지도 **자기** 번호를 보여 줍니다. 빌드 시각은 어느 컴퓨터에서 빌드해도 한국 시간으로 찍습니다.

## 7. 시험 중 SQLite 연결 약 1.4만 개가 닫히지 않음

**원인:** `with sqlite3.connect(path) as conn:`은 커밋·롤백만 하고 연결은 닫지 않습니다. Windows에서는 그동안 파일이 잠깁니다.

**해결:** `with` 블록이 끝나면 닫히는 연결 클래스(`ClosingConnection`)를 만들어 모든 DB 접근에 썼습니다.

---

## 8. 무료 음성 서비스가 예고 없이 403

**상황:** 기본 음성(edge-tts)은 공식 API가 아니어서 실제로 403으로 막힌 적이 있습니다.

**해결:** 403·연결 오류·30초 초과면 같은 성별의 유료 음성으로 **영상 전체를** 다시 읽습니다(문장마다 바꾸면 목소리가 섞임). 연속 3번 실패하면 10분 동안 건너뛰고, 어느 음성을 썼는지 작업 정보와 로그에 남겨 비용을 추적합니다.

## 9. CI에서만 가끔 실패하는 음성 인식 계산 시험

**상황:** 긴 음성을 조각으로 나눠 스펙트로그램을 만드는 코드가 "한 번에 만든 것과 숫자가 똑같다"를 비트 단위로 확인하는 시험이 있었습니다. 로컬과 지난 CI에서는 통과했는데, 어느 날 CI에서만 실패했습니다.

**원인:** 차이는 `0.58296204`와 `0.5829621`, float32 마지막 자리 하나였습니다. 검사 서버마다 CPU의 SIMD 폭이 달라 FFT 계산 순서가 조금씩 달라집니다.

**해결:** 비트 단위 비교 대신 `atol=1e-6`의 허용 오차로 바꾸고, 왜 그 값인지 시험에 주석으로 남겼습니다. 이 정도 차이로는 인식 결과(단어)가 바뀌지 않습니다.

**배운 점:** 실패한 시험을 "다시 돌리면 되는 것"으로 넘기지 않고, 무엇이 얼마나 달랐는지 확인한 뒤 기준을 의도에 맞게 고칩니다.

## 판단한 것들 (일부러 하지 않은 것)

- **OpenCV 5로 올리지 않음:** 5에는 얼굴 찾기(`CascadeClassifier`)가 빠져 긴 영상의 얼굴 따라가기가 깨집니다. 다른 방식(`FaceDetectorYN`)은 모델 파일과 품질 재측정이 필요해 따로 할 일로 남겼습니다.
- **React 린트 경고 44건 중 43건은 코드를 바꾸지 않음:** 대부분 "화면이 뜰 때 불러오기", "최신 값을 ref에 담기"처럼 일부러 쓴 흔한 방식이었습니다. 30곳을 고치면 버그 위험만 커져, 그 두 규칙만 이유를 적고 끄고 나머지 규칙은 유지했습니다. 남은 1건은 실제 버그가 아니어서 그 줄에만 이유를 적었습니다.
- **가입 때 "이미 가입된 이메일" 응답 유지:** 숨기려면 "가입하면 바로 로그인"을 포기해야 해 가입 전환율이 떨어집니다. 대신 IP당 가입 횟수 제한으로 대량 조회를 막았습니다.
